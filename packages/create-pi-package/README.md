# create-pi-package

Create PI packages for extensions, prompt templates, skills, themes, or any
combination of those resources.

`create-pi-package` is a small Commander CLI that scaffolds a publishable PI
package with the right `package.json` manifest, starter files, development
scripts, and follow-up generators for the resource types you choose.

## Requirements

- Node.js 20 or newer
- npm, pnpm, yarn, or bun

## Quick start

```bash
npm create pi-package
pnpm create pi-package
bun create pi-package
```

Create a package in a specific directory:

```bash
npm create pi-package my-pi-package
```

Pass non-interactive options after `--` with npm:

```bash
npm create pi-package my-pi-package -- --extensions --prompts --skills --bundle --bundler tsup --test-runner vitest
```

With pnpm or bun:

```bash
pnpm create pi-package my-pi-package --extensions --prompts --skills --bundle --bundler tsup
bun create pi-package my-pi-package --extensions --prompts --skills --bundle --bundler tsup
```

The `--` separator is only shown for npm argument forwarding. It is not needed
when running `create-pi-package` directly, and it is usually not needed for pnpm
or bun create commands.

## What it creates

The generated package can contain any of these PI resources:

- **Extensions**: TypeScript modules that register PI commands, tools, event
  handlers, and runtime behavior.
- **Prompt templates**: Markdown templates loaded as PI slash commands.
- **Skills**: Agent Skill folders with `SKILL.md` frontmatter and instructions.
- **Themes**: PI theme JSON files with the full required color-token set.

Generated packages include a `pi` manifest in `package.json`, for example:

```json
{
  "keywords": ["pi-package"],
  "pi": {
    "extensions": ["./extensions"],
    "prompts": ["./prompts"],
    "skills": ["./skills"],
    "themes": ["./themes"]
  }
}
```

PI can also discover conventional resource directories, but the explicit
manifest keeps package intent clear.

## Questionnaire behavior

The interactive flow asks only the questions needed for the selected resource
set.

- First choose what you are developing: extensions, prompts, themes, and/or
  skills.
- Extensions are handled first because they may need build and test tooling.
- Bundler and test-runner questions are only asked when extensions are selected.
- Prompt-only, skill-only, and theme-only packages do not ask bundler or
  test-runner questions.
- Themes can be generated by themselves or alongside the other resource types.

## CLI options

```txt
create-pi-package [directory] [options]
```

| Option | Description |
| --- | --- |
| `[directory]` | Folder to create the package in. Omit it to be prompted. |
| `--extensions` | Generate extension starter files and extension scaffold script. |
| `--prompts` | Generate prompt starter files and prompt scaffold script. |
| `--themes` | Generate theme starter files and theme scaffold script. |
| `--skills` | Generate skill starter files and skill scaffold script. |
| `--bundle` | Enable extension bundling. Only applies when extensions are selected. |
| `--no-bundle` | Disable extension bundling. |
| `--bundler <bundler>` | Extension bundler: `tsup` or `vite`. |
| `--test-runner <runner>` | Extension test runner: `vitest` or `jest`. |
| `--linter <linter>` | Linter to use: `eslint` or `biome`. Defaults to `eslint`. |
| `--formatter <formatter>` | Formatter to use: `prettier`, `stylistic`, or `biome`, depending on the selected linter. Defaults to the first valid formatter. |
| `--install` | Install development dependencies after scaffolding. |
| `--no-install` | Skip dependency installation. |
| `--force` | Overwrite managed scaffold files when they already exist. |
| `--help` | Show help. |
| `--version` | Show version. |

Invalid bundler, linter, formatter, and test-runner values fail before scaffolding starts.

Formatter choices depend on the selected linter:

| Linter | Valid formatters |
| --- | --- |
| `eslint` | `prettier`, `stylistic`, `biome` |
| `biome` | `prettier` |

`stylistic` means ESLint Stylistic and is only valid with ESLint.

## Resource examples

### Extension package

```bash
pnpm create pi-package my-extension-pack --extensions --bundle --bundler tsup --test-runner vitest
```

Creates:

```txt
extensions/example-extension.ts
test/example-extension.test.ts
scripts/create-extension.mjs
tsup.config.ts or vite.config.ts
vitest.config.ts or jest.config.js
```

Extension packages get:

- `npm run create:extension`
- bundler configuration when bundling is enabled
- a test suite matching the selected test runner
- `package.json` scripts and dev dependencies for the selected tools

### Prompt package

```bash
pnpm create pi-package my-prompts --prompts --no-install
```

Creates:

```txt
prompts/example-prompt.md
src/prompts/index.ts
scripts/create-prompt.mjs
```

Prompt-only packages skip bundler and test-runner setup.

### Skill package

```bash
pnpm create pi-package my-skills --skills --no-install
```

Creates:

```txt
skills/example-skill/SKILL.md
scripts/create-skill.mjs
```

The starter skill follows the PI Agent Skills convention with `name` and
`description` frontmatter.

### Theme package

```bash
pnpm create pi-package my-theme --themes --no-install
```

Creates:

```txt
themes/default.json
src/themes/index.ts
scripts/create-theme.mjs
```

The starter theme includes all required PI color tokens and a schema reference.

### Mixed package

```bash
pnpm create pi-package workflow-pack --extensions --prompts --skills --themes --bundle --bundler vite --test-runner vitest
```

Creates one starter example for every selected resource type and adds only the
follow-up scripts that match the selected types.

## Generated follow-up scripts

The generated package includes focused scripts for adding more resources later.
Each script accepts flags for automation and prompts for missing values.

### `npm run create:extension`

Available when extensions are selected.

```bash
npm run create:extension -- --name audit-helper
```

Creates:

```txt
extensions/audit-helper.ts
test/audit-helper.test.ts
```

The generated extension test file matches the package's selected test runner.
The script also records the package's selected bundler and test runner in its
output so users know which toolchain the extension is being created for.

### `npm run create:prompt`

Available when prompts are selected.

```bash
npm run create:prompt -- --name daily-review --body "Review today's changes."
npm run create:prompt -- --name daily-review --body-file ./prompt-body.md
```

Creates:

```txt
prompts/daily-review.md
```

### `npm run create:skill`

Available when skills are selected.

```bash
npm run create:skill -- --name release-check --description "Checks release readiness." --body "# Release Check"
npm run create:skill -- --name release-check --description "Checks release readiness." --body-file ./skill-body.md
```

Creates:

```txt
skills/release-check/SKILL.md
```

### `npm run create:theme`

Available when themes are selected.

```bash
npm run create:theme -- --name violet-night
```

Creates:

```txt
themes/violet-night.json
```

## Generated package scripts

Every generated package includes:

| Script | Purpose |
| --- | --- |
| `npm run dev` | Run the package entry file with `tsx`. |
| `npm run typecheck` | Type-check generated TypeScript. |
| `npm run build` | Build or validate output based on selected resource types. |

Extension packages may also include:

| Script | Purpose |
| --- | --- |
| `npm test` | Run Vitest or Jest, based on selection. |
| `npm run create:extension` | Scaffold another extension and matching test. |

Prompt, skill, and theme packages include the matching `create:*` script for
selected resource types.

## Package manager detection and dependency installation

Generated `package.json` files do not write `dependencies` or
`devDependencies`. Instead, `create-pi-package` calculates the development tools
needed for your choices and either installs them or prints the command to run
later.

When dependency installation is enabled, the CLI detects the package manager
from `npm_config_user_agent` or `npm_execpath` and runs the matching add command:

- `npm install --save-dev <packages...>`
- `pnpm add --save-dev <packages...>`
- `yarn add --dev <packages...>`
- `bun add --dev <packages...>`

When dependency installation is skipped, the summary prints the npm command as a
portable fallback.
## Publishing generated packages

Generated packages are normal npm packages. They include:

- `keywords: ["pi-package"]`
- a PI resource manifest
- `files` entries for generated resource directories and docs
- TypeScript declaration metadata via the `types` field

Before publishing, review generated code and run:

```bash
npm install --save-dev <printed packages>
npm run typecheck
npm run build
npm test # extension packages only, when a test runner was selected
```

PI packages run with full user permissions when installed, especially extension
packages. Review third-party packages before installing them.
